# Интернет-магазин «Технозавррр»

[English](README.md) | **Русский**

Одностраничный фронтенд интернет-магазина на Vue 2, Vuex и Vue Router. В нём есть каталог с фильтрами и пагинацией, страницы товаров и корзина, которая синхронизируется с сервером.

> 🎓 **Training project** · Skillbox · февраль–июнь 2023. Курс дал вёрстку, стили и публичное API (`vue-study.skillbox.cc`), код приложения писала я. Потом API отключили, и в сентябре 2026 я воспроизвела его контракт сама. Подробности в разделе [Что изменено позже](#что-изменено-позже).

**Live demo:** https://vue2-project-ten.vercel.app/

## Ключевое

- **Один REST-контракт и два взаимозаменяемых бэкенда.** Express-сервер и axios-адаптер в браузере отвечают на одни и те же запросы, поэтому демо — полностью статический сайт.
- **Проект пережил отключение API курса.** Я восстановила семь эндпоинтов, на которые опиралось приложение. Во фронтенде пришлось только вынести адрес API в переменную окружения и исправить запрос удаления из корзины: он неправильно передавал тело.
- **Оптимистичное обновление корзины с откатом.** Новое количество сразу попадает в Vuex, а если запрос не прошёл, состояние восстанавливается из последнего ответа сервера.
- **Корзина сохраняется после перезагрузки.** Она привязана к `userAccessKey`, который лежит в `localStorage`.
- **CI на каждый push.** GitHub Actions запускает ESLint и сборку демо.

## Возможности

- **Каталог** с серверной пагинацией и фильтрацией по категории и диапазону цен.
- **Страница товара** открывается по маршруту (`/product/:id`). На ней есть хлебные крошки категории, выбор количества и кнопка «В корзину» с состояниями загрузки и подтверждения.
- **Корзина** синхронизируется с бэкендом: товары можно добавлять, удалять и менять их количество. Счётчик в шапке и сумма заказа обновляются реактивно.
- При загрузке товаров показываются состояния загрузки и ошибки, есть кнопка повтора. У пустого каталога и пустой корзины свои заглушки.
- Фильтр цены проверяет ввод: отрицательные значения не принимаются, и «от» не может быть больше «до».
- Собственный компонент пагинации работает через `v-model`, а компонент фильтра — через модификатор `.sync`.

## Архитектура

```
pages / components ──► Vuex store ──► axios ──► API_BASE_URL
                                        │
                                        ├── Express mock server   (npm run serve)
                                        └── in-browser adapter    (demo mode, localStorage)
```

1. В [src/config.js](src/config.js) задан единственный `API_BASE_URL`, через него идут все запросы.
2. [src/store/index.js](src/store/index.js) хранит товары корзины и ключ доступа, а геттеры собирают подробный список корзины и итоговую сумму. Экшены корзины заменяют локальное состояние ответом сервера.
3. [MainPage](src/pages/MainPage.vue), [ProductPage](src/pages/ProductPage.vue) и [ProductFilter](src/components/ProductFilter.vue) запрашивают товары и категории напрямую, а операции с корзиной идут через экшены стора.
4. Запросы уходят в один из двух бэкендов с одинаковым контрактом:
   - [server/](server/) — Express-сервер, который держит корзины в памяти. Нужен для локальной разработки.
   - [src/mockApi.js](src/mockApi.js) — собственный axios-адаптер. Он отвечает на те же запросы прямо в браузере и хранит корзины в `localStorage`.

### Контракт API

| Метод | Эндпоинт | Назначение |
| --- | --- | --- |
| GET | `/api/products?page&limit&categoryId&minPrice&maxPrice` | Список товаров с пагинацией и фильтрами |
| GET | `/api/products/:id` | Один товар |
| GET | `/api/productCategories` | Категории для фильтра |
| GET | `/api/baskets?userAccessKey` | Текущая корзина (без ключа создаётся новая) |
| POST | `/api/baskets/products?userAccessKey` | Добавить товар `{productId, quantity}` |
| PUT | `/api/baskets/products?userAccessKey` | Изменить количество `{productId, quantity}` |
| DELETE | `/api/baskets/products?userAccessKey` | Удалить товар `{productId}` |

### Ключевые решения

- **Мок устроен как axios-адаптер, а не как отдельный адрес.** Режим сборки `demo` задаёт `VUE_APP_USE_MOCK=true` ([.env.demo](.env.demo)), и [src/main.js](src/main.js) подменяет `axios.defaults.adapter`. Компоненты и стор не знают, какой бэкенд им отвечает.
- **Источник правды для корзины — сервер.** После каждого запроса к корзине стор берёт список товаров из ответа и пересобирает по нему локальное состояние.
- **Роутинг в hash-режиме** (по умолчанию в Vue Router). Благодаря ему статическая сборка работает на Vercel без правил перезаписи.

## Запуск

Нужен Node.js 18+.

```bash
npm install
```

С Express-сервером (два терминала):

```bash
cd server && npm install && npm start   # API на http://localhost:3000
npm run serve                           # http://localhost:8080
```

Без сервера (мок в браузере):

```bash
npm run serve:demo   # http://localhost:8080
```

Другие скрипты:

```bash
npm run build        # продакшен-сборка под настоящий API
npm run build:demo   # продакшен-сборка с браузерным моком (для Vercel)
npm run lint         # ESLint
```

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `VUE_APP_API_BASE_URL` | `http://localhost:3000` | Базовый адрес API |
| `VUE_APP_USE_MOCK` | не задана (`true` в `--mode demo`) | `true` включает браузерный мок |

## Деплой

Демо лежит на Vercel как статический сайт: команда сборки `npm run build:demo`, папка с результатом `dist`. Для Express-сервера есть Dockerfile, но сам сервер нигде не размещён. Почему — написано в [server/README.md](server/README.md).

## Известные ограничения

- Вёрстка из шаблона курса не адаптивная и выглядит правильно только на десктопе.
- Выбранный цвет в фильтре запоминается, но не отправляется в API. Чекбоксы «объём» статичные.
- На странице товара вместо реальных данных статичные описание, вкладки и варианты объёма памяти.
- У корзины нет состояний загрузки и ошибки, поэтому пользователь не узнаёт о неудачных запросах.
- Кнопка «Оформить заказ» ни к чему не подключена.
- Express-сервер держит корзины в памяти, и после перезапуска они теряются.

## Что бы я улучшила

- **Адаптивная вёрстка и проверка доступности**, в том числе навигация с клавиатуры и ARIA для счётчика корзины и фильтров.
- **Фильтры и текущая страница в query-параметрах URL**, чтобы отфильтрованной выдачей можно было поделиться и она не сбрасывалась при перезагрузке.
- **Отдельный модуль для работы с API.** Я бы вынесла запросы из компонентов и показывала ошибки тостами, а не прямо в разметке.
- **Тесты:** юнит-тесты стора, мока API и компонентов, e2e-тест сценария с корзиной.
- **Настоящая страница товара** с галереей и картинки в WebP с `srcset`.
- **Оформление заказа** и хостинг для Express-сервера, чтобы в демо можно было показать настоящий бэкенд.
